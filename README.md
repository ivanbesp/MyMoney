# 🌱 Финансовый трекер

Личный трекер финансов — минималистичный, приятный, функциональный.

## Возможности

- ✅ Доходы и расходы с категориями и подкатегориями
- ✅ Управление категориями (добавить, изменить, удалить)
- ✅ Статистика за день / неделю / месяц / год / всё время
- ✅ Диаграммы: динамика и расходы по категориям
- ✅ Копилки с прогресс-баром и дедлайнами
- ✅ **Финансовый пульс** — индикатор здоровья бюджета
- ✅ **Инсайты** — умные советы на основе ваших данных
- ✅ Мультивалютность: RUB / USD / EUR с ручными курсами
- ✅ Резервная копия JSON и экспорт в CSV
- ✅ Все данные хранятся в localStorage (приватно, офлайн)

## Как устроены даты и валюты

Две вещи, которые легко сломать обратно, поэтому они вынесены явно.

**Даты — календарные, строкой `YYYY-MM-DD`, в локальном времени.** Нигде не
используется `toISOString()`: он отдаёт UTC, и запись уезжает на соседний день —
в UTC+ ломался график, в UTC− пропадал фильтр «Сегодня». Все преобразования
живут в `lib/dates.ts`, сравнение периодов — лексикографическое по строкам.

**Курс фиксируется в момент создания операции** (поле `rate` — сколько рублей
стоила единица валюты). Правка курсов в настройках влияет только на новые
записи; суммы уже внесённых операций не пересчитываются задним числом.

## Запуск локально

```bash
npm install
npm run dev        # http://localhost:3000
npm run typecheck  # проверка типов
npm test           # тесты логики: миграции, даты, курсы, бэкап
npm run test:tz    # те же тесты в четырёх часовых поясах
```

## Деплой на GitHub Pages

Всё уже настроено: при пуше в `main` workflow собирает статику и публикует её.

1. Создайте репозиторий на GitHub (публичный — Pages на бесплатном тарифе
   работает только с публичными).
2. В репозитории: **Settings → Pages → Source → GitHub Actions**.
3. Свяжите папку с новым репозиторием и запушьте:

```bash
git remote set-url origin https://github.com/ВАШ_ЛОГИН/ИМЯ_РЕПО.git
git add -A
git commit -m "GitHub Pages"
git push -u origin main
```

`basePath` вычисляется из `GITHUB_REPOSITORY` автоматически, поэтому конфиг
править под имя репозитория не нужно. Файл `public/.nojekyll` обязателен:
без него Jekyll выбрасывает папку `_next`, и страница открывается пустой.

**Важно про данные.** `github.io` — другой домен, чем Vercel, и localStorage
туда не переедет. Перед переходом выгрузите резервную копию в настройках
и загрузите её на новом адресе.

## Деплой на Vercel

1. Залей проект на GitHub
2. Зайди на [vercel.com](https://vercel.com) → New Project
3. Выбери репозиторий → Deploy
4. Готово! Vercel сам определит Next.js

Или через CLI:
```bash
npm i -g vercel
vercel
```
